# 证据等级与信号强度

> 来源：用户已有美客多选品 Skill 的 `evidence-levels.md` 与 `data-audit.md`，按其实质合并移植。
> 每个关键数据都必须附来源、采集时间、证据等级；没有来源的数据不得进入评分或利润计算，只能标待核实。

## 证据等级（5 档）

| 等级 | 定义 |
|---|---|
| 已核实 | 凭证已提供，或在官方页面、卖家后台亲眼看到 |
| 页面可见 | 平台公开页面可见，但没有后台或凭证复核 |
| 用户提供 | 用户提供，还没有外部复核 |
| 待核实 | 还没有来源，上架前必须核实 |
| 推测 | 只是推理，不是事实，不能打满分 |

- 推测不能用来给需求、利润或合规打满分。
- 待核实、推测、有冲突的数据一律需要人工复核。

## 信号强度

- 强信号：墨西哥站畅销区、搜索结果页、同类目多卖家在售、页面可见已售提示。
- 中信号：热词出现、个别卖家在售、用户自己的历史销售或咨询记录。
- 弱信号：创作者活动、Linktree 活动入口、短视频播放和点赞、社媒讨论热度。
- 弱信号的正确用法：把它当作“值得去站内查一下”的线索，不要直接当作需求证据打高分。
- Linktree 本身不提供销量榜、搜索量、排名。活动页只能当入口，不能当热度结论。

## 常见错误

- 把“很多创作者在推”写成“这个品卖得火”。
- 把搜索结果的第一页写成官方排名。
- 把供应商说的销量写成平台销量。
- 把一次大促的单日表现写成长期需求。

## 禁止的转换

以下转换一律禁止：

- 不得把搜索结果排名直接写成销量或市场份额。
- 不得把页面已售提示直接写成近 30 天销量或转化率。
- 不得把创作者推广、短视频热度、Linktree 活动入口直接写成销量。
- 不得把供应商口头描述的销量直接写成平台销量。
- 不得把一次大促的单日表现直接写成长期需求。

## 数据审计记录字段

每条关键数据都要留一条审计记录，字段如下：

| 字段 | 说明 |
|---|---|
| 数据内容 | 具体数字或结论，例如售价 199 MXN（MLM）或 149 BRL（MLB）、同款卖家数 12 家；金额必须带市场货币，不得只写数字 |
| 数据来源 | 页面链接、文件名称、供应商名称、用户口头提供，要写清到可复查的程度 |
| 来源类型 | 官方页面、卖家后台、供应商文件、用户提供、第三方公开信息、推测，只能六选一 |
| 获取日期 | 看到或收到该数据的日期 |
| 证据等级 | 已核实、页面可见、用户提供、待核实、推测，五档严格区分 |
| 是否存在冲突 | 有冲突时两边都要写，写清冲突点 |
| 可信度 | 高、中、低。已核实和官方页面一般为高，页面可见为中，用户提供和第三方为中或低，推测为低 |
| 是否需要人工复核 | 是或否。待核实、推测、有冲突的数据一律为是 |

## 费用来源要求

- 平台费用、税费、进口相关费用、物流费用都要注明来源及适用条件，例如“用户提供的费率，适用于某类目，尚未在卖家后台复核”。
- 没有可靠数据时，用用户确认的假设做模拟，并明确标注“模拟结果，不代表实际费用”。
