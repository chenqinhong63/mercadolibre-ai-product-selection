# Mercado Libre Sales Trend Analysis — 销量趋势分析

## Purpose

看一个（或几个）具体商品的销量随时间怎么变，回答：**它是在涨、在稳、
还是在跌？有没有季节性？**

本 Skill 只描述已经发生的历史趋势，**趋势是历史记录，不是销量预测**——
不预测未来销量，不写“下个月能卖多少”，不给 GO / CONDITIONAL / NO-GO
结论（那是 Skill 6 的事），不算利润（那是 Skill 7 的事）。

适用范围：Mercado Libre 墨西哥站（`market_code` MLM）与巴西站 Mercado Livre
（`market_code` MLB）。**`market_code` 是必填参数**：MLM 或 MLB，二选一。
用户没给 `market_code` 时先问用户，**不默认 MLM、不默认墨西哥**；用户明确
要巴西时绝不按墨西哥跑。两站的数据、关键词语言、货币、费率互不通用。

## Input / Output Contract

| 方向 | 内容 |
|---|---|
| 消耗（输入） | `market_code`（MLM 或 MLB，必填）+ `sku_id`（一个或一份短名单，来自 Skill 2 / 3）；可选：分析天数 `days`（≤731）、用户关心的起止月份 |
| 产出（输出） | 本文件 §输出模板 的月度 + 周度趋势表、涨跌解读、季节性提示、Confirmed / Emerging / Fading 定级及依据；下游 Skill 6 消费定级与依据，作为需求证据的一部分 |
| 不产出 | 销量预测、GO / CONDITIONAL / NO-GO verdict、评分、利润测算 |

## Inputs

### 必填

- **市场代码 `market_code`**：`MLM`（墨西哥站）或 `MLB`（巴西站）。
  缺失时先问用户，不假设、不默认 MLM。
- **`sku_id`**：一个，或一份短名单（建议一次不超过 5 个；超过 5 个分批跑，
  每批都要先查配额）。
  `sku_id` 一般来自 Skill 2 的候选清单或 Skill 3 的 Top-5 拆解表。
  `sku_id` 前缀按市场区分：MLM 开头为 `MLM...`，MLB 开头为 `MLB...`；
  前缀与 `market_code` 不一致时停下问用户，不拿错市场的商品趋势当结论。

### 语言检查（必做，付费调用前——仅当本 Skill 需用关键词复核快照时）

- MLM 关键词只用西语，MLB 关键词只用葡语；**两个市场都不用中文关键词**。
- 用户给了中文关键词，或给了错市场语言的关键词（例如巴西站给西语
  `cuerda para saltar`、墨西哥站给葡语 `corda para pular`），**停下并
  请用户提供/确认正确语言的关键词**。不静默翻译、不把错语言词直接
  拿去调付费接口。
- 正确语言示例：MLM 西语 `cuerda para saltar`；MLB 葡语 `corda para pular`。
- 本 Skill 主键是 `sku_id`，不靠关键词定趋势；关键词只在快照复核步使用。

### 货币规则

- MLM 价格一律 MXN，MLB 价格一律 BRL；同一张表里不得混用两种货币，
  不得用自编汇率换算。跨市场对比被要求时，MXN 与 BRL 两列并排展示，
  换算栏目标“待核实”，除非用户提供了汇率 + 日期。

### 可选

- **分析天数 `days`**：最长 731 天；不给时默认取工具允许的完整区间，
  并在输出里写清实际覆盖的起止日期。
- **用户关心的起止月份**：例如“只看 2026 年以来的趋势”；有则按该窗口
  解读，无则按完整返回区间解读，不擅自裁剪数据。

### 缺失时怎么办

- 缺 `market_code`：先问用户，不默认 MLM。
- 无 `sku_id`：先问用户要，或请用户先跑 Skill 2 / 3 拿到 `sku_id`；
  **不要用商品标题、关键词代替 `sku_id` 去调 `product_sales_trend`**，
  该工具只认 `sku_id`。
- `sku_id` 无效 / 工具查无此商品：如实写“该 `sku_id` 无趋势数据”，
  不换一个近似商品顶替。

## Damaishuju MCP Calls

唯一数据源：大麦数据 MCP（`custom.damaishuju`）。
本 Skill 只用其中 3 个。调用前先读
`~/workspace/custom-connectors/custom.damaishuju/CONNECTOR.md`。

### 调用顺序

1. **`get_my_quota_status`（免费）——先查配额，再做任何付费调用。**
   无参数。读 `available_points`（2026-11-23 实测为 50，无套餐，
   `plan_code` / `plan_name` 均为 null）。
   剩余点数不足时停下并告诉用户，不静默烧完；短名单分批跑时每批
   前都重新查一次配额。
   注意：**单次付费调用扣几分未知**，永远不要声称某次调用扣了多少分；
   只记录调用前后的 `available_points` 实测差值。
2. **`search_product_snapshots`（付费）——确认 `sku_id` 并取 30/60/90 天销量。**
   参数示例：
   `{"market_code": "<MLM 或 MLB>", "keyword": "<市场语言关键词，如有>", "category_id": "<id，如有>", "sort_by": "sales_30d", "limit": <小数目>}`，
   示例：MLM `{"market_code": "MLM", "keyword": "cuerda para saltar"}`；
   MLB `{"market_code": "MLB", "keyword": "corda para pular"}`。
   从返回结果里取目标商品的 `sku_id` 与 `sales_30d` / `sales_60d` / `sales_90d`。
   若用户直接给了 `sku_id` 且无需核对，可跳过本步，但须在输出里写明
   “`sku_id` 由用户提供，未经快照复核”。
3. **`product_sales_trend`（付费）——按 `sku_id` 取月度与周度销量。**
   参数示例：
   `{"sku_id": "<sku_id>", "market_code": "<MLM 或 MLB>", "days": <≤731>}`。
   每个 `sku_id` 各调一次；短名单多个商品时逐个调，不要合并成一次调用
   去猜参数（工具是单品口径）。

### 缓存（14 天）

- 同一 `sku_id` + `days` 的趋势结果缓存 14 天（key 含 `sku_id`、
  `days`、`market_code`）。
- 缓存只在调用完整成功后写；失败、超时、返回为空不写缓存。

### 调用记录

每次调用记录：工具名、参数、调用时间、返回条数、调用前后的
`available_points`。附在输出末尾。

## Analysis Steps

0. **确认市场与语言**：先确认 `market_code`（缺失先问，不默认 MLM）；
   `sku_id` 前缀须与市场一致；如需关键词复核，先过语言检查（MLM 西语 /
   MLB 葡语，中文与错市场语言关键词一律停下问用户）。未通过不调付费接口。
1. **确认 `sku_id`**：用快照复核 `sku_id` 与商品标题是否一致；
   不一致时停下问用户，不拿错商品的趋势当结论。
2. **取趋势数据**：`product_sales_trend` 返回月度与周度销量，
   只写工具实际返回的字段；缺失的周 / 月写“—（工具未返回）”，
   不插值、不补 0（缺失不等于 0 销量）。
3. **算变化**：月度环比 `MoM = (本月 − 上月) / 上月 × 100%`，
   周度环比同理；只在相邻两期都有数据时算。
   同时对照快照的 `sales_30d / 60d / 90d` 做交叉核对：
   三者口径应大体一致（90 天 ≥ 60 天 ≥ 30 天的累计关系以工具定义为准，
   本 Skill 不自创换算公式）；明显矛盾时两边都写，标待核实。
4. **读涨跌**：只描述已发生的走势——持续上升 / 平稳 / 持续下滑 /
   波动，并写清依据区间（例：近 3 个月连续下滑）。
   单月或单周的涨跌不单独下结论，要看连续 2–3 期的方向。
5. **看季节性**：对照过去 12 个月（`days` 覆盖不足 12 个月时写清
   “覆盖不足一年，季节性判断受限”），标出明显高于 / 低于其余月份的
   月份；**一次大促的单日表现不得写成长期需求**（见 §证据与局限）。
6. **定级**：按下列标准给每个 `sku_id` 定级（移植 FlatNine `trend-alert`
   的速度分组，只复用分组名与思路，阈值按本 Skill 的定义执行）：
   - **Confirmed（已确认趋势）**：近 3 个月及以上销量持续处于高位或
     持续上升，且周度数据不矛盾；依据：列出连续月份数值。
   - **Emerging（新出现趋势）**：近 1–2 个月明显上升，但历史不足
     3 个月，或周度数据尚未稳定；依据：列出上升的起止月份与幅度。
   - **Fading（正在衰退）**：近 2–3 个月持续下滑，或销量已回落到
     上升前水平；依据：列出下滑的起止月份与幅度。
   - 无法定级时写“数据不足，无法定级”，并写清缺什么（覆盖天数不足、
     关键月份缺失等），不强行定级。
7. **写缺口**：覆盖天数、缺失月份、快照与趋势矛盾点，逐项列入
   “尚未核实”，交给 Skill 6 复核。

## Error Handling

| 情况 | 做法 |
|---|---|
| 无 `sku_id` | 先问用户要，或请用户先跑 Skill 2 / 3；不用标题、关键词代替 `sku_id` |
| `sku_id` 无效 / 查无此商品 | 如实写“该 `sku_id` 无趋势数据”，不换近似商品顶替 |
| 快照与趋势销量明显矛盾 | 两边都写，写清矛盾点，标待核实，不只挑有利的一边 |
| 趋势数据缺失月份 / 周 | 缺失写“—（工具未返回）”，不插值、不补 0 |
| `days` > 731 | 工具上限为 731 天，超限时按 731 取，并写清实际覆盖区间 |
| 覆盖不足 12 个月 | 季节性判断写“受限”，不定季节性结论 |
| 配额不足 | 停下，告诉用户当前剩余点数；短名单分批跑时每批前重查配额 |
| 调用超时 45 秒 | 先用只读查询确认状态再决定是否重试，失败重试最多 1 次（仅瞬时错误） |
| 401 / 403 | 先查凭证与 placement（见 CONNECTOR.md），不盲重试 |

## Evidence & Limits

### 证据等级（五档，V2.1 原样沿用）

- **已核实**：凭证已提供，或在官方页面、卖家后台亲眼看到。
- **页面可见**：平台公开页面可见，但没有后台或凭证复核。
  大麦工具返回的原始数据在本 Skill 里按此档标注。
- **用户提供**：用户提供，还没有外部复核。
- **待核实**：还没有来源，必须在上架前核实。
- **推测**：只是推理，不是事实。推测不能用来给需求、利润或合规打满分。

每条关键数据都要写来源、采集时间、证据等级三项。

### 禁止的转换（一条都不能做）

- 不得把搜索结果排名直接写成销量或市场份额。
- 不得把页面已售提示直接写成近 30 天销量或转化率。
- 不得把创作者推广、短视频热度、Linktree 活动入口直接写成销量。
- 不得把供应商口头描述的销量直接写成平台销量。
- 不得把一次大促的单日表现直接写成长期需求。

### 局限

- **趋势是历史，不是预测**：Confirmed 只表示“过去这段时间卖得稳/涨”，
  不表示“未来还会涨”；Emerging / Fading 同理。任何把趋势读数写成
  未来销量预测的表述都是违规的。
- 单月或单周的涨跌不单独下结论；定级至少看连续 2–3 期的方向。
- 季节性判断需要至少 12 个月覆盖；不足一年时只写“受限”，不定结论。
- `sales_30d/60d/90d` 与趋势序列的口径以工具返回为准，本 Skill
  不自创换算公式、不把 30 天销量乘 12 当成年销量。
- 费率未核实：本 Skill 不涉及利润与费率，任何佣金、运费、税费数字
  都不得在本 Skill 的输出里出现。巴西站费率/税费同样待核实，不得把
  墨西哥的费率、MSI 或税率套到巴西站。
- 唯一已核实的税费口径（**仅限墨西哥站**，Mercado Pago 官方博客 2026-05-15，
  2026-11-23 访问）：有 RFC 时 ISR 2.5%、IVA 代扣 8%；
  无 RFC 时 ISR 20%、IVA 16%。本 Skill 不做税务计算。
  **巴西站不适用，巴西税费待核实**——不得把上述 ISR/IVA 数字套到巴西站，
  也不得自编任何巴西佣金/税率。
