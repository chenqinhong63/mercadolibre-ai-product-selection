# ml-market-report-generator — 市场报告生成器

## 目的

把 Skills 1–7 的输出拼成一份统一的 Markdown 报告，让用户一次看清：结论是什么、证据是什么、哪些还没核实、下一步做什么。本 Skill 只汇总和排版，**不重新调查、不重新算分、不编新数据**。报告里的每个数字都必须能在上游输出里找到来源；找不到的写“待核实”，不补数。

## 市场参数（market_code，第一位参数）

- `market_code` 必填，二选一：`MLM` = Mercado Libre México（墨西哥站，货币 MXN，语言西语）或 `MLB` = Mercado Livre Brasil（巴西站，货币 BRL，语言葡语）。
- **如果 `market_code` 缺失，先问用户，不默认 MLM。** 绝不以“用户没说就按墨西哥”静默处理；用户明确要求巴西时，一律按 MLB 走。
- 货币：MLM 一律 MXN，MLB 一律 BRL。**绝不混用两种货币，绝不用自编汇率换算。** 跨市场对比时，两种货币并列呈现，换算写“待核实”，除非用户提供了汇率 + 日期。
- 语言：MLM 只用西语，MLB 只用葡语，绝不用中文关键词；客户原话、关键词保留原文语言（西语或葡语）。
- 巴西站（MLB）费率 / 税费一律待核实：不要把墨西哥的 ISR / IVA 代扣、MXN 费用或 MSI 分期照搬到巴西，也不要自编任何巴西佣金 / 税率。

模板结构来源：Nexscope Tier A 报告模板（竞品 / 价格 / 评论 / 利润 / 跨境报告结构）+ Aron 的产品档案（dossier）模式 + SkillShelf 的基础文档串联；内容、数据源和数值一律按本系统（大麦 MCP + V2.1）重写，不复制 Nexscope / Cart / Accio 的品牌文案和 upsell。

## 输入

本 Skill **不直接调大麦 MCP**，只读上游输出。

| 输入来源 | 本报告用的部分 |
|---|---|
| `market_code` | 必填：`MLM` 或 `MLB`。缺失时先问用户，不默认 MLM。 |
| Skill 1（ml-market-research） | 市场 / 类目结论 |
| Skill 2（ml-product-discovery） | 发现短名单、候选品、售价（MLM 为 MXN，MLB 为 BRL）、价格带 |
| Skill 3（ml-competitor-analysis） | 竞争结构、头部卖家分析 |
| Skill 4（ml-sales-trend-analysis） | 销量趋势结论 |
| Skill 5（ml-review-intelligence） | 主题、痛点、好评、功能需求、宣称核对 |
| Skill 6（ml-product-opportunity-scoring） | 六项分数、verdict、失败五问、低成本验证方案、15 项短名单 |
| Skill 7（ml-profit-analysis） | 三层利润、反向推导、压力测试（金额带市场货币） |
| 用户补充 | 报告用途、候选品范围、已知的最新变化（如有） |

**缺失处理**：某 Skill 没跑过，对应章节写“本次未执行 <Skill 名>，本节待补充”，不编内容冒充已跑；某候选品缺某项数据，写“待核实”，不从别的候选品挪数字。

## 汇总规则

1. **每个结论只写一次**：同一分数、同一句话不在不同章节重复出现。执行摘要里写结论，证据章节写依据，评分章节写分数——摘要不贴完整分数表，评分章节不重复摘要的判断句。
2. **每个结论带证据等级或待核实**：结论后面跟（证据等级：已核实 / 页面可见 / 用户提供 / 待核实 / 推测）或直接写“待核实”。
3. **示例 / 虚构数字必须标注**：模板里的占位数字、举例数字一律标“（示例数字，非真实数据）”；真实报告里不得出现未标注的示例数字。
4. **冲突不平均**：上游结论冲突时两边都写，写清冲突点和需要人工复核的问题，不要只挑有利的一边。
5. **不做禁止的转换**：不把搜索排名写成销量，不把页面已售提示写成 30 天销量，不把创作者热度写成销量，不把评论数写成销量。
6. **语言与单位**：分析用中文，关键词和引用用原文语言（MLM 西语 / MLB 葡语）；价格一律带市场货币（MLM 为 MXN，MLB 为 BRL），绝不混用；日期一律写采集时间。跨市场对比时两种货币并列，换算写“待核实”，除非用户提供了汇率 + 日期。
7. **GO 的含义**：报告里每次出现 GO 都按 V2.1 解释——“值得进入下一轮人工核查和小批量验证”，不是“可以直接发布”，更不是“可以直接大量备货”。

## 错误处理

| 情况 | 做法 |
|---|---|
| 某 Skill 输出缺失 | 对应章节写“本次未执行 <Skill 名>，本节待补充”，不编内容。 |
| 上游数字对不上（如 Skill 6 的售价与 Skill 7 的售价不一致） | 两边都写进数据审计表的冲突栏，报告里用较早 / 较可信的一方并注明冲突，不悄悄改数。 |
| 候选品超过 15 个 | 只列 Skill 6 短名单里的品，其余进附录清单（品名 + verdict + 一句话原因），不扩充正文表格。 |
| 用户要求删掉某章节 | 可以删，但删除后在报告顶部写“应用户要求，本报告未含 <章节名>”，不假装它本来就不存在。 |
| 报告里出现示例数字 | 必须标“（示例数字，非真实数据）”；交付前自查一遍，未标注的示例数字一律删掉或标注。 |

## 证据与局限

- 证据等级（V2.1 五档）：已核实、页面可见、用户提供、待核实、推测。本报告不产生新证据等级，只搬运上游的等级；上游没给等级的数据，本报告写“待核实”。
- 数据审计表是本报告的必备部分：每条关键数据都要有来源、来源类型、采集日期、证据等级、冲突、可信度、是否需要人工复核，缺一项就写“待核实”，不留空。
- 局限：本报告汇总的是研究时点的快照，价格、卖家数、趋势都会变；结论有效期以数据采集时间为准，过期数据要重新跑 Skills 1–7；本报告不代替卖家后台的最终审核，不代替品牌授权核实。
- 费率说明：平台费率、税费、广告、分期等百分比以用户提供或官方来源核实为准；已核实的只有 Mercado Pago 代扣（有 RFC：ISR 2.5%、IVA 8%；无 RFC：ISR 20%、IVA 16%），且代扣不是全部税费成本——报告里引用时必须写清这一点。**上述代扣仅限墨西哥站（MLM），巴西站不适用，巴西税费待核实；不要把墨西哥 ISR / IVA 费率、MXN 费用或 MSI 分期照搬到巴西，也不要自编任何巴西佣金 / 税率。**

## 输入 / 输出契约（供串联）

- 输入：`market_code`（必填，`MLM` 或 `MLB`；缺失时先问用户，不默认 MLM）+ Skills 1–7 的输出（见“输入”一节）+ 用户补充的报告用途和候选品范围。所有金额带市场货币（MLM 为 MXN，MLB 为 BRL），绝不混用。
- 输出：一份按上节模板的 Markdown 报告，标题顺序固定，含执行摘要与结论表、市场、发现短名单、竞争、趋势、评论、评分、利润、风险、验证计划、数据审计表、下一步行动（1–3 个）。
- 上游：Skills 1–7；下游：无（本 Skill 是流水线终点，报告交给用户审阅）。**不直接调 MCP。**
