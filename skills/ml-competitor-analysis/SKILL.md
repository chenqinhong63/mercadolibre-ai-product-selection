# Mercado Libre Competitor Analysis — 竞品分析

## Purpose

拆头部 5 个 listing，回答两个问题：

1. **这个品类的竞争结构是什么样的？**（价格带、卖家数量结构、头部强在哪）
2. **新卖家凭什么获得订单？**（具体打法，不是“做好服务”）

本 Skill 不给 GO / CONDITIONAL / NO-GO 结论（那是 Skill 6 的事），不算利润
（那是 Skill 7 的事），不分析评论内容（那是 Skill 5 的事）。
本 Skill 的输出供 Skill 6 的竞争结构打分与新卖家降级规则直接引用。

适用范围：Mercado Libre 墨西哥站（`market_code` MLM）与巴西站 Mercado Livre
（`market_code` MLB）。**`market_code` 是必填参数**：MLM 或 MLB，二选一。
用户没给 `market_code` 时先问用户，**不默认 MLM、不默认墨西哥**；用户明确
要巴西时绝不按墨西哥跑。两站的数据、关键词语言、货币、费率互不通用。
**MLM / MLB 都是平台，不是独立站**：本 Skill 没有商店流量、技术栈、独立站广告
等字段；任何“店铺流量 / 技术栈”类结论都不写，写了就是编造。
巴西站文案与评价为葡语，巴西费率/税费待核实，不得把墨西哥的费率、MSI
或 ISR/IVA 税率套到巴西站。

## Input / Output Contract

| 方向 | 内容 |
|---|---|
| 消耗（输入） | `market_code`（MLM 或 MLB，必填）+ `category_id` 或市场语言关键词 + 候选 `sku_id`（可选，来自 Skill 2）；可选：Skill 2 的候选清单 |
| 产出（输出） | 本文件 §输出模板 的 Top-5 拆解表 + 价格带 + 卖家数量结构 + 新卖家进入分析；下游 Skill 6 消费价格带、卖家数结构带（≤5 / 6–15 / 16–30 / >30）、新卖家问题答案与差异化可执行性 |
| 不产出 | GO / CONDITIONAL / NO-GO verdict、评分、利润测算、评论主题分析 |

## Inputs

### 必填

- **市场代码 `market_code`**：`MLM`（墨西哥站）或 `MLB`（巴西站）。
  缺失时先问用户，不假设、不默认 MLM。
- 以下二选一：
  - **`category_id`**（来自 Skill 1 / Skill 2），或
  - **市场语言关键词**（用于 `search_product_snapshots` 的 `keyword`）：
    MLM 西语，例如 `cuerda para saltar`；MLB 葡语，例如 `corda para pular`。
    中文关键词不支持。

### 语言检查（必做，付费调用前）

- MLM 关键词只用西语，MLB 关键词只用葡语；**两个市场都不用中文关键词**。
- 用户给了中文关键词，或给了错市场语言的关键词（例如巴西站给西语
  `cuerda para saltar`、墨西哥站给葡语 `corda para pular`），**停下并
  请用户提供/确认正确语言的关键词**。不静默翻译、不把错语言词直接
  拿去调付费接口。

### 货币规则

- MLM 价格一律 MXN，MLB 价格一律 BRL；同一张表里不得混用两种货币，
  不得用自编汇率换算。跨市场对比被要求时，MXN 与 BRL 两列并排展示，
  换算栏目标“待核实”，除非用户提供了汇率 + 日期。

### 可选

- 候选 `sku_id`（来自 Skill 2 的候选清单）：有则在拆解表里标出候选品
  在 Top-5 中的位置（在 / 不在前 5），没有则不写。
- 用户已知的头部卖家信息（卖家名、listing 链接）：只作交叉核对的线索，
  不作为数据来源；工具返回与用户说法冲突时两边都写。

### 缺失时怎么办

- 缺 `market_code`：先问用户，不默认 MLM。
- 既无 `category_id` 又无市场语言关键词：先问用户要其中一个，不要自己
  编一个关键词去查（关键词是付费调用的入参）。
- 无候选 `sku_id`：照常做品类级 Top-5 拆解，在输出里写“本次未绑定候选品，
  新卖家分析按品类通用打法写，候选品确定后须复核”。

## Damaishuju MCP Calls

唯一数据源：大麦数据 MCP（`custom.damaishuju`）。
本 Skill 只用其中 2 个。调用前先读
`~/workspace/custom-connectors/custom.damaishuju/CONNECTOR.md`。

### 调用顺序

1. **`get_my_quota_status`（免费）——先查配额，再做任何付费调用。**
   无参数。读 `available_points`（2026-11-23 实测为 50，无套餐，
   `plan_code` / `plan_name` 均为 null）。
   剩余点数不足时停下并告诉用户，不静默烧完。
   注意：**单次付费调用扣几分未知**，永远不要声称某次调用扣了多少分；
   只记录调用前后的 `available_points` 实测差值。
2. **`search_product_snapshots`（付费）——取同类目销量前列的 listing。**
   参数示例：
   `{"market_code": "<MLM 或 MLB>", "keyword": "<市场语言关键词>", "category_id": "<id，如有>", "sort_by": "sales_30d", "limit": <取 Top  listing 所需的小数目，如 20–30>}`。
   示例：MLM `{"market_code": "MLM", "keyword": "cuerda para saltar"}`；
   MLB `{"market_code": "MLB", "keyword": "corda para pular"}`。
   `sku_id` 前缀按市场区分：MLM 开头为 `MLM...`，MLB 开头为 `MLB...`。
   - `keyword` 必须是市场语言（MLM 西语 / MLB 葡语）；有 `category_id` 时优先用 `category_id`
     限定范围，关键词作辅助。
   - `sort_by` 固定为 `sales_30d`；**排序只是工具返回的顺序，
     不是官方排名**，不得写成“平台第 × 名”。
   - `limit` 取够 Top-5 拆解所需即可（考虑去重与字段缺失，取 20–30 合理），
     不要一次拉全量。
   - 同一关键词 / 类目 14 天内不重复调。

如需看某个头部 listing 的更多字段，用同一工具、同一 `sku_id` 条件
复查，不要换工具、不要编字段。

### 缓存（14 天）

- 同一关键词 / 类目 / 筛选组合的快照结果缓存 14 天（key 含全部筛选条件 hash）。
- 缓存只在调用完整成功后写；失败、超时、返回为空不写缓存。

### 调用记录

每次调用记录：工具名、参数、调用时间、返回条数、调用前后的
`available_points`。附在输出末尾。

## Analysis Steps

0. **语言检查**：先确认 `market_code`（缺失先问，不默认 MLM）与关键词语言
   是否匹配市场（MLM 西语 / MLB 葡语，中文关键词与错市场语言关键词一律
   停下问用户，见 §Inputs 语言检查）。语言未通过不调任何付费接口。
1. **取 Top-5**：按 `sales_30d` 降序取前 5 个 listing（去重：同一卖家
   多个同款变体只计一次，备注里写清去重规则）。不足 5 个时如实写
   “本次仅返回 n 个”，不凑数。
2. **逐个拆解**：按 §输出模板的拆解表逐项填，只写工具实际返回的字段：
   价格、sales_30d、评分、评论数、卖家类型、stock_type、店铺字段。
   工具没返回的字段写“—（工具未返回）”，不要从标题或图片推测。
3. **算价格带**：对 Top-5 价格（样本不足时对本次返回的全部价格）算
   min / max / median / Q1 / Q3（定价统计逻辑，移植 FlatNine
   `pricing-intel`；确定性实现为 `scripts/pricing_stats.py`，见评估报告
   §5.1，该脚本未就绪前按下列定义手工算，结果须可复算）：
   - median：排序后中间值（偶数个取中间两数均值）。
   - Q1：下四分位数（排序后前 25% 位置的值）；Q3：上四分位数（后 25%）。
   - 候选品价格落点：低于 Q1 / Q1–median / median–Q3 / 高于 Q3，
     写清落点，不写“定价合理”这种判断（定价判断是 Skill 6 / 7 的事）。
   - 离群值处理：价格为 0 或高于中位数 10 倍的，先标出并排除在统计外，
     排除理由写清。
4. **判卖家数量结构**：按本次返回的同款 / 同类卖家数落带（V2.1 口径，
   仅作结构描述，不直接打分）：
   ≤5 家 / 6–15 家 / 16–30 家 / >30 家；卖家数未知时写“未知（待核实）”，
   不编一个数字落带。
5. **拆头部经营质量**：逐项写头部优势——价格竞争强度、评价数量与质量、
   变体与套装结构、物流与配送优势（工具返回的 stock_type / 发货字段
   为准）、难以复制的优势（品牌、评价积累等，未知写待核实）。
   头部 3 个以上都是绿标加 Full 加包邮时，先写“正面拼价难”，再写换打法。
6. **回答新卖家问题**：按 V2.1 `new-seller-analysis.md`，必须具体回答
   “我进入这个市场，凭什么获得订单？”打法只能从以下八种里选，
   每种都要写清成本、物流影响、买家是否需要、对手复制难度、能否支撑更高售价：
   规格、套装组合、使用场景、配件组合、供应链优势、售后服务、商品设计、
   细分人群。**只写“优化包装”“提升质量”“做好服务”不算差异化方案。**
   答不出来时如实写“无法回答新卖家问题”，并按 V2.1 规则注明：
   该候选在 Skill 6 应先判 CONDITIONAL（新卖家进入理由不成立）。
7. **判复制风险**：差异点只是价格或一张主图时，复制风险判高；
   差异点是规格、套装、供应链或售后能力时判相对低，但仍要写清对手
   复制需要的时间和成本，未知时写待核实，不编数字。
8. **写缺口**：工具未返回的字段、无法确认的头部优势，逐项列入
   “尚未核实”，交给 Skill 5（评论）/ Skill 6 复核。

## Error Handling

| 情况 | 做法 |
|---|---|
| 无 `category_id` 且无关键词 | 先问用户要其中一个，不自己编关键词 |
| 返回不足 5 个 listing | 如实写实际个数，不凑数、不从别的品类补 |
| 同一卖家多个同款变体占满 Top-5 | 去重后只计一次，备注写清去重规则；去重后不足 5 个如实写 |
| 关键字段缺失（如无 stock_type / 卖家类型） | 缺失写“—（工具未返回）”，相关判断写待核实，不推测 |
| 卖家数未知 | 写“未知（待核实）”，不编数字落带 |
| 配额不足 | 停下，告诉用户当前剩余点数，不要先烧再说 |
| 调用超时 45 秒 | 先用只读查询确认状态再决定是否重试，失败重试最多 1 次（仅瞬时错误） |
| 401 / 403 | 先查凭证与 placement（见 CONNECTOR.md），不盲重试 |
| 工具返回与用户提供的头部信息冲突 | 两边都写，写清冲突点，标待核实 |

## Evidence & Limits

### 证据等级（五档，V2.1 原样沿用）

- **已核实**：凭证已提供，或在官方页面、卖家后台亲眼看到。
- **页面可见**：平台公开页面可见，但没有后台或凭证复核。
  大麦工具返回的原始数据在本 Skill 里按此档标注。
- **用户提供**：用户提供，还没有外部复核。
- **待核实**：还没有来源，必须在上架前核实。
- **推测**：只是推理，不是事实。推测不能用来给需求、利润或合规打满分。

每条关键数据都要写来源、采集时间、证据等级三项。

### 禁止的转换（一条都不能做）

- 不得把搜索结果排名直接写成销量或市场份额。
- 不得把页面已售提示直接写成近 30 天销量或转化率。
- 不得把创作者推广、短视频热度、Linktree 活动入口直接写成销量。
- 不得把供应商口头描述的销量直接写成平台销量。
- 不得把一次大促的单日表现直接写成长期需求。

### 局限

- 本 Skill 没有商店流量、技术栈、独立站广告字段：MLM / MLB 都是平台，
  任何这类结论都是编造，一律不写。
- 价格带统计样本小（Top-5 或本次返回数）时结论只作方向性；
  样本 <10 时在价格带一节显著提示样本不足。
- 评分、评论数是工具返回的快照值，不验证真伪、不换算成销量；
  评论内容分析是 Skill 5 的事。
- 费率未核实：美客多佣金比例、固定费用、免运费门槛、MSI 分期成本等
  均未核实，本 Skill 不写任何费率数字；物流优势只按工具返回的
  stock_type / 发货字段描述，不折算成费用。巴西站费率/税费同样待核实，
  **不得把墨西哥的费率、MSI 或 ISR/IVA 税率套到巴西站，也不得自编
  任何巴西佣金/税率**。
- 本 Skill 不给 verdict：新卖家问题答不出来时，只注明
  “Skill 6 应先判 CONDITIONAL”，不等同于本 Skill 判了 CONDITIONAL。
